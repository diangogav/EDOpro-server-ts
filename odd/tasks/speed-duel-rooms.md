# Speed Duel rooms created by our server

Objective: one of our own clients asks for a Speed Duel room and the server creates it on the EDOPro core with the format's settings, seating our clients through the cross-play bridge; no native EDOPro client involved.
Branches: `feat/speed-duel-rooms` in `EDOpro-server-ts` and in `evolution-card-game`. Delivery strategy: `ask-on-risk`; the client deploys on merge, so it must be harmless against a server that does not know the command yet.
Test runner: server `pnpm test <path>`, `npx biome lint src docs`; client `npx vitest run <files>`, `npm run typecheck`, `npm run check:svelte`, `npm run build`.

Reference for every EDOPro rule: `/home/diango/Code/ygo/Multirole` (official server) and `/home/diango/Code/ygo/edopro` (client), read-only.

## Specs

- **S1 — How a room is asked for.** As proposed and accepted: "eliges 'Speed Duel' como formato al crear sala, igual que Rush o Edison. Por debajo es un token `speed` en la orden de sala. Dos jugadores que escriben el mismo nombre de sala se encuentran, como en los demás formatos."
  - Acceptance: a join command whose tokens include `speed` creates the room when no waiting Speed Duel room has that name and password, and joins it when one does; the room is an EDOPro-core room and the player is seated through the bridge. `m` (match) and the room name/password are honoured; a duel that already started is not joined as a player.
- **S2 — The room's settings.** As proposed and accepted: "4000 LP, mano inicial de 4, robo de 1. Mazos de 20-30, Extra de 0-6, Side de 0-6. Lista Speed 2025.07. Duelo suelto o match, según elijas." and "LP y mano fijos. No se podrían cambiar con las opciones de sala, para que una sala Speed sea siempre Speed."
  - Duel flags are EDOPro's Speed Duel mode (`0x628000`, high word 0), forbidden types 0, as its host form sets them (`edopro/gframe/menu_handler.cpp:976-1001`). `lp`, `st` and `dr` tokens do not change a Speed Duel room.
  - The ban list is the Speed Duel list the EDOPro flow already loads (`resources/current/edopro/lflists/Speed.lflist.conf`, name `2025.07 Speed Duel`), found by name pattern, not by a dated literal.
- **S3 — Allowed cards.** As accepted: "Cartas permitidas: solo las de la lista Speed. La lista blanca hace de único filtro." Verified: the Skill Cards of the EDOPro card file carry scope `0x40` (174 of them), `0x4` (19) or `0x1040` (33), which the OCG/TCG scopes reject as unofficial (`Multirole/src/Multirole/Room/Context.cpp:345-410`). So the room is created with the "anything goes" scope (4) and the whitelist decides.
- **S4 — The client knows the room.** The client must treat the room as one run by the EDOPro core: no 40-card pre-check, EDOPro card data and prompt strings, the Skill slot. Agreed mechanism: the client recognises a command with the `speed` token the way it recognises `edo,<id>`. The lobby names the ban list: the hash the room announces must be the one the client computes for that list (the client's whitelist hash differs from EDOPro's: it XORs `0x0f0f0f0f`; see `evolution-card-game/src/features/cards/domain/LFList.ts:117,160` and `src/ygopro/edopro-bridge/ownBanListHash.ts`).
  - Acceptance: with the format "Speed Duel" chosen in the lobby's room creation, a 20-card deck readies; the lobby shows the Speed Duel list by name; LP and starting hand are not offered for that format.
- **S5 — The room survives its first player.** As accepted: "Si el primer jugador se va de la espera, la sala sigue y el otro pasa a ser anfitrión." Today the host leaving a waiting EDOPro room deletes it and closes every socket (`EdoproDisconnectPolicy.ts:36-44`).
  - Acceptance: only for rooms the server created this way; a room hosted by a native EDOPro client keeps today's behaviour. An empty server-created room is removed.
- **S6 — Nothing else changes.** Rooms hosted from EDOPro, `edo,<id>` joins, and every YGOPro-flow command behave as before. The `speed` token is no longer "unrecognized" for the YGOPro flow, but it must never create a YGOPro room; ban list indices of the YGOPro catalog do not change (the Speed list is not added to the YGOPro runtime pool).

Accepted out of scope for this version: "Espectadores. Repeticiones. Bots. Ranked y matchmaking. Las salas serían sin estadísticas." Reconnection keeps its known gaps.
